# 编辑、采集、审查、AI 修复闭环

本次修改覆盖人工编辑状态、采集投递恢复、空结果审查和失败证据包。保持现有管理后台布局；正式采集仍由人工点击发起，自动恢复只继续已经被人工请求的轮次。

## 升级

先备份独立平台库，再执行 `alembic upgrade head`。采集投递表由
`0007_collection_dispatch` 创建；当前项目还包含后续批量导入迁移
`0008_batch_intake`，不要将已有数据库降级：

```powershell
docker compose build api worker openhands-agent-server
docker compose run --rm --no-deps api alembic upgrade head
docker compose up -d --no-build api worker openhands-agent-server scheduler
```

代码和清洗库仍分离。采集记录的 `platform_id`、`entity_id` 保持为空；候选只创建本地提交。

## 三条状态路径

| 操作 | 后端行为 | 验收条件 |
| --- | --- | --- |
| 保存人工编辑版本 | 建立 `manual_edit` 轮次，生成对应报告并绑定独立 Spec revision；需要人工确认字段对齐 | 审查通过或重投通知后，不调用 `inspect_site`，不覆盖旧版本 |
| 点击启动采集 | 同一事务保存采集轮次、幂等事件和 `collection_dispatches` 投递记录 | Broker 暂时故障后补投；相同请求编号不重复创建轮次 |
| 成功采集 0 条 | 人工确认观察范围内无岗位、无实习或证据不足；如果官网有岗位但未采到，则提交漏采问题进入 AI 诊断 | 两个分支都填写依据，不生成虚假记录、不自动采纳候选 |

人工编辑保留原 Spec 的字段映射，并生成 `NEEDS_REVIEW` 修订；不会凭代码文本猜测新的字段语义。后续 AI 修复使用被审查代码绑定的 Spec 与失败快照，可以提交有证据支持的修订。

采集投递的身份是固定的 `manual_run_id`。`PENDING` 表示等待投递，`SENT` 表示已发送，`RUNNING` 携带执行所有者和心跳，`DONE` 表示该轮次已结束。消息重复时只允许一个所有者执行。心跳失效后恢复同一轮次，旧进程失去写入权；连续恢复三次仍中断则转人工。排队中停止不依赖 worker 收到原消息。

## 空结果接口

在数据页选择具体轮次，点击“处理空结果”。也可调用：

```text
POST /api/v1/admin/runs/{manual_run_id}/finalize
```

```json
{
  "review_status": "NO_DATA_CONFIRMED",
  "observation_code": "INCONCLUSIVE",
  "comment": "本次记录为空，尚未取得足够证据判断招聘入口是否有岗位",
  "client_request_id": "empty-review-20260930-001"
}
```

`observation_code` 允许 `NO_JOBS_OBSERVED`、`NO_INTERNSHIPS_OBSERVED`、`INCONCLUSIVE`。成功后保存人工依据、采集参数范围和代码版本，轮次为 `REVIEWED`；任务显示“空结果已确认”，候选采纳状态保持不变。有记录、采集失败、版本过期或缺少依据时拒绝确认。

若同样的入口和筛选条件在官网有岗位、本轮却返回 0 条，在“处理空结果”中选择
“官网有岗位但未采到，提交 AI 排查”。接口使用 `review_status=CODE_FIX_REQUIRED`，
并在 `comment` 写入核对依据。后端保存轮次级 `missing` 问题、空记录快照和运行诊断，
生成失败包；没有记录时不会伪造 `sample_index`。空白说明会被拒绝，重复提交不会重复修复。

## 失败包提供给 Agent 的内容

失败包版本为 `failure-bundle-v2`，绑定实际被审查的 `submission_id`、提交 SHA、`manual_run_id`、Spec revision 与 hash。

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 版本、范围、问题、样本索引、证据引用与哈希 |
| `samples/<index>.json` | 对应岗位原始记录、实际字段值、人工预期及说明 |
| `records.json` | 本轮完整脱敏记录；原采集文件另保留用于追溯 |
| `collection-diagnostics.json` | 运行参数、起止时间、环境标识、错误、采集输出和关联日志 |
| `platform-spec.json` | 被审查代码对应的不可变 Spec 快照 |
| `platform-spec-schema.json` | 当前 Pydantic 契约，供编写合法补丁 |

Agent 使用读取工具的 `area=failure` 读取本失败包目录；不能访问其他任务或通过路径穿越扩大范围。旧采集记录不会因修复而改写。

代码修复后的回归失败仍携带原失败包的引用。Spec 补丁格式错误会转成结构化验证反馈，并附带 JSON Schema，进入有次数限制的修复循环；不把格式错误标记为成功，也不允许补丁更改权限、ID、正文规范或验收规则。
