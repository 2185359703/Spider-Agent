# 采集器接入工作流

## 1. 输入与边界

输入是一条或一批公司招聘入口 URL。只读源仓库用于理解既有架构和协议实现；所有生成与修复都在 AI 产出仓库的独立 worktree 中完成。不得修改其它工作区，也不得把未提交变更带入基线。

控制面和 `PlatformSpec` 中的 `platform_id`、`entity_id` 在清洗映射前始终为 `null`。候选 TOML 省略 `platform_id`，由后续确认的环境变量提供正式编号。

## 2. 真实协议分析

按以下顺序取证：

1. 打开招聘入口，保存脱敏页面、请求清单、响应清单和必要响应体。
2. 确认岗位列表请求的方法、URL、query/body、响应封装和岗位数组位置。
3. 确认详情请求或证明列表数据已包含完整正文。
4. 验证分页参数、起点、步长、总数和终止条件。
5. 确认发布时间字段；取不到时保留空值。
6. 确认实习筛选来自哪些明确字段，并检查服务端筛选是否真实生效。
7. 若响应加密、编码或签名，保存可重放证据并实现确定性解码。

遇到失败时先区分层级：DNS/TLS/连接重置/超时、系统代理、访问限制、反爬响应、列表解析、详情解析、分页和字段映射。分别测试环境代理与直连，不得无证据地固定 `trust_env=False` 或切换请求库。只有可由代码或配置稳定解决的问题进入代码修复。

## 3. PlatformSpec

证据先生成版本化 `PlatformSpec`，再生成 Python、TOML、fixture 和测试。Spec 是权威输入；派生代码不能反向改写证据结论。低置信度字段必须标记并进入人工重点审查。

## 4. 生成与自动验证

Agent 在白名单内生成一个平台采集器、一个 TOML、专项测试和脱敏 fixture。运行语法、专项 pytest、Ruff、契约、业务规则和真实接口门禁。

自动汇报必须区分：

- `INTERNSHIPS_FOUND`：验证范围内存在实习岗位；
- `NO_INTERNSHIPS_OBSERVED`：存在岗位列表，但验证范围内未匹配实习；
- `NO_JOBS_OBSERVED`：列表可访问且当前为空；
- `NO_JOB_LIST_FOUND`：没有可验证的岗位列表入口；
- `ACCESS_RESTRICTED`：访问限制使证据不足；
- `INCONCLUSIVE`：现有证据不能可靠分类。

不能把网络错误、解码错误或解析异常汇报成“无岗位”。

验证通过后生成本地候选 commit，`push_status=DISABLED`。候选和证据必须绑定 commit、基线、Spec revision 和运行轮次。

## 5. 人工运行与审查

正式采集始终由人工触发。平台登记运行命令、环境指纹、候选 commit、开始/结束时间、脱敏日志和岗位样本。

人工逐样本检查 ID、标题、URL、地点、正文、要求、发布时间、实习筛选和分页完整性：

- 正确：采纳该特定 commit；
- 代码或配置可修复：生成失败纠错包并进入 AI 修复；
- 外部网络/权限阻断：保留证据并请求输入，不进行无关代码改动；
- 业务规则歧义：进入人工规则确认；
- 明确不可用：拒绝当前候选。

“已采纳”只代表人工认可候选采集结果，不代表已推送、已合并、已写入旧原始库或已完成下游实体映射。

## 6. AI 修复闭环

失败纠错包包含期望与实际结果、字段问题、样本索引、候选 commit、Spec、脱敏响应和证据引用。Agent 从失败 commit 创建新 worktree，先复现再修复，补充回归测试，并重新执行全部门禁和真实采集。修复产生新 commit，不能覆盖旧候选历史。

代码可解决的范围包括错误 endpoint/request、稳定解码、分页、字段选择器、过滤、格式归一化和可复现的代理配置。纯外部网络波动、凭证缺失、访问权限或网站暂时不可用不应通过猜测代码来“修复”。

## 7. 数据与职责分离

数据流为：平台采集器 → 统一原始记录 → 人工审查 → 后续映射/清洗。采集器不写 SQL，仓储层不发网络请求。原始 payload 保留可重放业务数据并删除敏感字段；正文使用统一规范化逻辑。未映射记录可暂存和审查，但旧原始库写入必须因 `source_platform=None` 被阻断。
