# 招聘采集管理后台

在 `D:\Project\Auto_spider\frontend` 运行：

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:5173`。Vite 将 `/api` 代理到本机 `18000` 的真实 FastAPI；不配置 API 也不会进入模拟数据模式。API 暂时不可用时，页面显示错误与重试按钮。

```powershell
npm run build
```

构建结果在 `dist/`。部署静态页面时需要将前端路径回退到 `index.html`，并将 `/api` 反向代理到 FastAPI。也可使用 `VITE_API_BASE_URL` 指定 API，`VITE_USER_ID` / `VITE_USER_ROLE` 沿用平台已有的身份配置。

## 六个模块

| 地址 | 用途 |
| --- | --- |
| `/companies` | 公司一行，展开招聘入口，新增接入、人工启动采集 |
| `/data` | 按公司、入口、轮次筛选完整采集记录，导出、提交最终审查 |
| `/data/review?task=...&run=...&index=1` | 逐条核对标题、描述、要求，查看 JSON / HTML，记录问题 |
| `/code?task=...&submission=...` | 固定 Git 提交的文件树、源码、历史、差异、验证结果 |
| `/status?task=...&run=...` | 工作流 checkpoint、接入汇报、失败包和暂停/恢复/重试 |
| `/logs?task=...&run=...` | 每 2 秒按 sequence 增量读取事件，搜索、过滤、跟随、导出 |
| `/settings` | 服务状态、三个仓库的实际边界、规则草稿与历史 |

公司、入口、提交与轮次写入 URL，刷新和跨页面跳转保留上下文。采集器仓库与 AI 管理平台仓库独立；历史记录引用的提交若不在指定采集代码仓库，显示不可用，不使用其他项目补齐。

## 人工采集与审核

1. 在公司页或代码页点击启动采集，选择已采纳版本或当前候选版本。
2. 默认采集实习岗位；可以限制最近 N 天的发布时间范围。缺失发布时间的岗位保留，显示未提供。
3. 后端将固定提交导出为独立目录，由 Celery 在 Linux Landlock 中运行 `CollectorRegistry`，不调用旧项目的数据库写入服务。高级参数的分页安全上限、HTTP 请求间隔和执行时限实际生效。请求间隔由隔离进程统一约束 requests / httpx / curl_cffi 客户端。
4. 完整结果保存为脱敏证据 JSON，数据库记录轮次、文件引用和审查决定。数据页服务端分页，不截取前三条样本冒充完整数据。
5. 标题、描述、要求来自 `raw_content.job`，页面只转为安全可读文本；不调用 AI 改写正文。原始 JSON 保留。API 采集没有保存 HTML 时明确显示缺失，不生成官网快照。
6. 单条通过/问题立即保存；最终审查单独提交。未审查岗位不会自动通过。当前候选通过最终审查才采纳；已采纳版本重复运行的通过审查不会误采纳其他候选。
7. 采集错误或人工问题可以提交失败纠错包；是否能通过代码修复由既有诊断流程决定。历史版本被替代时保留单条审查，最终采纳必须使用当前候选。

同一招聘入口不能并发运行。重复请求幂等，停止操作与日志停止跟随互相独立。该后台不提供定时采集或网站变化监控。
